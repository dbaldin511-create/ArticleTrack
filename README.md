## ArticleTrack

ArticleTrack — консольное приложение для учёта статей в журнале. Проект предназначен для автоматизации основных процессов работы редакции: подачи статей авторами и рассмотрения их редакторами. Приложение позволяет регистрировать пользователей, выполнять авторизацию и работать с данными журнала, включая статьи, рубрики и решения по статьям.

## Возможности

В проекте реализованы следующие основные возможности:

- регистрация авторов;
- авторизация пользователей;
- подача статьи автором (название, аннотация, рубрика, файл);
- проверка автором статуса своей статьи;
- просмотр редактором списка статей на рассмотрении;
- принятие решения по статье («Принята» / «Отклонена»);
- сохранение даты подачи и даты решения;
- хранение данных в базе данных.

## Архитектура

Приложение построено с использованием многослойной архитектуры.

```
Пользователь
     │
     ▼
Консольный интерфейс
(main.py, menu.py, auth.py)
     │
     ▼
Сервисный слой
(services)
     │
     ▼
Слой доступа к данным
(repositories)
     │
     ▼
База данных
(database)
```

Такое разделение позволяет отделить пользовательский интерфейс от бизнес-логики и операций с данными.

## Основные компоненты

### main.py
Точка входа в приложение. Выполняет инициализацию необходимых компонентов и запускает программу.

### menu.py
Содержит логику взаимодействия с пользователем через консольное меню. Состав меню зависит от роли пользователя.

### auth.py
Отвечает за регистрацию и авторизацию пользователей, а также за проверку роли.

### models
Содержит модели основных сущностей предметной области: пользователи, статьи, рубрики.

### repositories
Содержит компоненты, отвечающие за получение, добавление, изменение и удаление данных.

### services
Содержит бизнес-логику приложения (подача статьи, смена статуса, формирование списка статей на рассмотрении) и обеспечивает взаимодействие между пользовательским интерфейсом и слоем доступа к данным.

### database
Содержит компоненты, необходимые для работы с базой данных и её инициализации.

## Роли и сценарии

| Роль | Доступные действия |
|------|--------------------|
| Автор | авторизоваться, подать статью, проверить статус статьи |
| Редактор | авторизоваться, просмотреть список статей на рассмотрении, принять решение по статье |

Статья проходит через статусы: **«На рассмотрении»** → **«Принята»** или **«Отклонена»**.

Диаграмма вариантов использования и блок-схемы сценариев находятся в папке `docs/`.

## Требования

Для запуска проекта необходимо установить:

- Python 3.13 или выше;
- Git.

## Установка

### 1. Клонирование репозитория

```
git clone <repository-url>
cd ArticleTrack
```

### 2. Создание виртуального окружения

```
python -m venv .venv
```

### 3. Активация виртуального окружения

Windows PowerShell:

```
.venv\Scripts\Activate.ps1
```

Windows Command Prompt:

```
.venv\Scripts\activate.bat
```

Linux и macOS:

```
source .venv/bin/activate
```

### 4. Установка зависимостей

```
pip install -r requirements.txt
```

## Запуск приложения

Из корневой папки проекта выполните:

```
python -m src.articletrack.main
```

После запуска в консоли будет отображено главное меню приложения.

```
===== Журнал =====
1. Вход
2. Регистрация автора
0. Выход
```

Пользователь может выбрать необходимое действие, введя соответствующий номер.

## Работа в Visual Studio Code

Для запуска проекта в Visual Studio Code необходимо выбрать интерпретатор Python из виртуального окружения:

```
.venv\Scripts\python.exe
```

Конфигурация запуска находится в файле:

```
.vscode/launch.json
```

Проект запускается как Python-модуль:

```
src.articletrack.main
```

Это позволяет корректно использовать пакетную структуру проекта и абсолютные импорты.

## Разработка

Исходный код проекта располагается в каталоге:

```
src/articletrack/
```

При разработке рекомендуется соблюдать следующую организацию кода:

- модели предметной области размещать в `models`;
- работу с базой данных размещать в `repositories`;
- бизнес-логику размещать в `services`;
- код пользовательского интерфейса размещать отдельно от бизнес-логики.
